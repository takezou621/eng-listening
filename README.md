# 英語リスニングアプリ 企画・仕様書

個人開発の英語リスニングアプリにおいて最大のボトルネックは「**高品質かつ権利関係がクリーンな音声・スクリプト素材の調達コスト**」です。

既存のニュースやYouTubeの無断スクレイピング・音声抽出は利用規約違反および著作権侵害のリスクが高く、アプリストアの審査リジェクトや公開後の削除対象になります。法的に100%クリアな状態を保ちつつ、個人開発でも運用コストを抑えて学習効果の高いアプリを作るための企画・仕様案をまとめました。

## 1. 著作権・法的リスクをクリアする3つのコンテンツ調達戦略

アプリの性質や開発工数に合わせて、以下のいずれか（または組み合わせ）を採用します。

| 調達アプローチ | 具体的なソース・手法 | 法的クリアの根拠 | メリット・デメリット |
| --- | --- | --- | --- |
| **A. 生成AIによる完全オリジナル生成（最有力）** | LLM（GPT-4o / Claude / Gemini等）でスクリプト生成 ＋ 高品質TTS（OpenAI TTS / ElevenLabs / Azure Speech等）で音声化 | AI生成物の著作権ポリシーに基づき開発者側で権利を保有可能（商用利用可のAPIプラン利用が前提） | ◎ 権利問題ゼロ。レベル・トピック・話速・アクセントを自由自在に制御可能。<br>△ API従量課金が発生するため、事前生成＋キャッシュ設計が必須。 |
| **B. パブリックドメイン / CCライセンス活用** | ・LibriVox（著作権切れ文学の朗読音声＋Gutenbergのテキスト）<br>・Tatoeba（CC-BYの例文＋音声）<br>・VOA Learning English（※米国政府著作物＝原則パブリックドメインだが、一部外部素材が含まれるため利用規約の精査が必要） | 著作権保護期間満了、またはクリエイティブ・コモンズ（帰属表示など条件遵守）による利用許諾 | ◎ 音声制作コストがゼロ。<br>△ 古典文学は現代の日常会話と語彙が異なる。CC-BYはクレジット表記UIが必要。 |
| **C. ユーザー持ち込み型（BYOC）** | ユーザー自身が購入した音声ファイル（MP3等）やテキスト、または端末のローカルファイルを読み込ませるプレイヤー型 | 開発者は「再生・学習ツール（器）」のみを提供し、コンテンツを配信しない | ◎ サーバー費用・権利リスクが極小。<br>△ ユーザーが自分で素材を用意する手間があり、離脱率が高くなりやすい。 |

> **推奨構成**
> 「**A（AI事前生成コンテンツの配信）**」をベースにしつつ、上級者向けに「**C（ローカルファイル読み込み）**」をサブ機能として持たせるのが、法的安全性とユーザー体験のバランスが最も優れています。

## 2. アプリ企画概要

### コンセプト

**「『音の変化』と『チャンク理解』を可視化する、精聴特化型リスニングトレーナー」**

単なる聞き流しプレイヤーではなく、学習ステップ（リンキング理解 → スクリプト確認 → シャドーイング → チャンク理解）を最短距離で回すためのUI/UXに特化します。

### ターゲット層

- 単語や文法は中学〜高校レベルを知っているが、ネイティブのスピードになると聞き取れない初級〜中級者（TOEIC 400〜750点層）
- 隙間時間（1回3〜5分）で効率的にトレーニングしたい社会人・学生

## 3. 機能仕様書（MVP：最小限の製品）

個人開発で初期リリースまで最速で漕ぎ着けるためのコア機能です。

### ① コンテンツ再生・表示画面（メインUI）

#### タイムスタンプ同期スクリプト（カラオケ表示）

- 音声の再生位置に合わせて、該当する英文がリアルタイムでハイライトされる
  - Whisper等の強制アライメントで単語・フレーズ単位のタイムスタンプを事前生成
- タップした文の頭から即座にリプレイ可能

#### 「音の変化（リンキング・リダクション）」可視化モード

- スクリプト上に発音記号やカタカナではなく、以下を視覚的にオーバーレイ表示（オン/オフ切替）
  - つながる音（⌒）
  - 消える音（薄字）
  - フラッピング（t→r表記）
- **実装方法**: スクリプト生成時にLLMへプロンプトでリンキング箇所のメタデータ（JSON）を出力させる

#### スラッシュ（意味の塊）表示切替

- 英語の語順のまま理解するため、チャンクごとの区切り線（/）とチャンク単位の直訳を表示するトグル

#### 学習特化型プレイヤー制御

- **ABリピート**: 聞き取れない1文だけを無限ループ
- **再生速度変更**: 0.7x / 0.85x / 1.0x / 1.2x（ピッチ補正あり）
- **シャドーイング録音＆比較**: 自分の声をマイク録音し、お手本音声と交互・同時に再生して発音やリズムのズレを確認
  - 音声データは端末内メモリのみで処理し、サーバーには保存しない

### ② コンテンツライブラリ（AI事前生成）

APIコスト爆発を防ぐため、ユーザーのリクエストごとにリアルタイム生成するのではなく、管理側でバッチ生成したコンテンツを静的ファイル（JSON + MP3/AAC）としてCDN（Cloudflare R2等）から配信します。

- **シチュエーション別ミニ会話（30〜60秒）**: カフェ、空港、ビジネス会議、日常の雑談など
- **ニュース・解説風モノローグ（1〜2分）**: テクノロジー、科学、ライフハックなど興味を持ちやすいテーマ
- **難易度別バリエーション**: 同一トピックで以下を用意
  - 初級（ゆっくり・基本語彙）
  - 中級（ナチュラル速度・リンキング多め）

### ③ 学習進捗・復習機能

- **苦手フレーズ帳（ワンタップ保存）**: 聞き取れなかった文をブックマークし、後で苦手な文だけを連続シャドーイングできるプレイリスト機能
- **学習時間・シャドーイング回数の可視化**: 継続モチベーション維持のためのシンプルなヒートマップや連続日数表示

## 4. 推奨技術スタック（低コスト・高スケーラビリティ構成）

個人開発で維持費（固定費）をほぼゼロに抑えつつ、クロスプラットフォームで展開する構成例です。

### フロントエンド（モバイル / Web）

- **Flutter** または **React Native (Expo)**
  - iOS / Android同時展開
  - 音声再生・録音には `just_audio` や `expo-av` を使用
- Webアプリとして展開する場合は **Next.js**（PWA化すればスマホでもアプリ感覚で動作）

### バックエンド / コンテンツ配信

- **Cloudflare R2 + Workers**
  - R2はエグレス（転送量）無料のため、音声ファイル配信の通信費を劇的に抑えられる
- **Supabase** または **Firebase**
  - 認証、ブックマーク・学習履歴の同期用

### コンテンツ生成パイプライン（ローカル/バッチ処理）

| 用途 | 使用技術 |
| --- | --- |
| スクリプト＆リンキング解析 | OpenAI API / Claude API / Gemini API（Structured Outputsでタイムスタンプ用テキストとリンキング位置JSONを出力） |
| 音声合成（TTS） | OpenAI TTS (`tts-1-hd`) または Azure AI Speech（SSMLタグで話速やポーズを細かく制御可能） |
| 単語レベルタイムスタンプ抽出 | `faster-whisper`（ローカルGPU等で実行すればAPIコスト無料） |

## 5. 法的コンプライアンス・ストア審査対策チェックリスト

リリース前に以下の規約・表記を整備しておくことで、法務リスクとストア審査リジェクトを回避します。

- [ ] **利用規約（Terms of Service）の明記**
  - アプリ内コンテンツの著作権は開発者に帰属し、無断転載・再配布・商用利用を禁止する旨を記載
  - AI生成コンテンツを含むため、情報の正確性（ハルシネーション等）に関する免責事項を記載
- [ ] **TTS / LLMサービスの商用利用条件の確認**
  - 使用するAPIの規約を確認（例：OpenAI APIやAzureは出力物の商用利用を許可しているが、一部音声モデルでは「AI生成音声であることの開示」が求められる場合がある）
  - 必要に応じて「※音声はAIにより生成されています」とクレジット表記を入れる
- [ ] **プライバシーポリシー（マイク権限の扱い）**
  - シャドーイング機能でマイクを使用するため、iOS（`NSMicrophoneUsageDescription`）およびAndroidで「発音練習の録音にのみ使用し、外部サーバーへ送信・保存しない」ことを明記
- [ ] **BYOC（ユーザーファイル読み込み）機能を入れる場合の注意**
  - YouTubeのURLを貼って音声をダウンロードさせるような機能は、YouTube利用規約違反となりApp Store / Google Playで確実にリジェクトされるため**実装しない**（あくまで端末内のローカル音声ファイル選択にとどめる）
