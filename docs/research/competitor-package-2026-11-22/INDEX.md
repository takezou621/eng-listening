# 競合リサーチパッケージ（ミミトレ ブラッシュアップ用）

作成: 2026-11-22、Muse（事業責任者）が Antigravity への依頼に先立って用意した。
対象アプリ: ミミトレ - 英語の音が見える（eng-listening / React Native + Expo）

## このパッケージの使い方

1. まず本 INDEX と `../competitor-package-2026-11-22` 内の各社 `brief.md` を読むこと
2. 画面の実物は各社 `screenshots/`（App Store 公式スクリーンショット）と `metadata.json`（ストア説明文・評価）で確認すること
3. 操作の流れ・遷移の感覚は `videos.md` の動画、詳細な手順は `articles.md` の記事で確認すること
4. より深いインタラクション調査（9観点×5社の採点と採用/回避リスト）は `reference/competitor-interaction-research-2026-11-22.md`、画面比較は `reference/competitor-ui-comparison-2026-11-21.md` を参照すること

## 競合6社の要約

| アプリ | 強み | ミミトレへの示唆 |
|---|---|---|
| Duolingo | 習慣化とゲーム化の完成度 | ストリーク救済、単線導線、フィードバックの多重表現 |
| ELSA Speak | 発音のスコア可視化 | 診断結果の「スコア+形」表現、目標→分量の自動決定 |
| Speak | レッスン内3段構成 | 聞く→型→話すの段階設計、復習の自動提示 |
| スピークバディ | 診断→AIカリキュラム提案 | 段階的に支えを外す会話設計、診断結果からの接続 |
| abceed | 予測スコアと学習分析 | 量の見える化、誤答の自動収集→再出題 |
| シャドテン | シャドーイング手順のシステム化 | ステップ明示、客観指標（WPM）、録音ループの完結 |

## ブラッシュアップの優先順位（監督側の指定）

依頼本文（Antigravity への指示書）に詳述するが、骨子は次のとおり。

1. レッスン画面の再構成（Issue #45）: 聞く/読む/話す/スクリプトのモード排他化、解説のボトムシート化、シャドーイングの1文フォーカス化。競合では Speak の3段構成とシャドテンのステップ固定が手本
2. 進捗・継続の仕組み（Issue #46 の残り）: ストリーク救済（E16、Duolingo のフリーズが手本）、1日の目標設定（ELSA のコーチ式、abceed の学習時間設定が手本）
3. ライブラリのタイトル階層（E15）: 日本語/英語の主従を競合のカード表現と比べて判断する

## 制約（必ず守ること）

- UI 原則ルールブック `docs/ui-design-rules.md`（P1〜P7、作業規則 W1〜W8）が絶対の基準。新規違反を作らない
- 変更は画面ごとにライト/ダーク両モードのスクリーンショットで検証する（W7）
- `npm run typecheck` と `npm run lint` を通すこと
- 課金（RevenueCat）、法務文言、価格、ストア情報には触れない
- 作業は機能ブランチ + PR 形式。main へ直接コミットしない
