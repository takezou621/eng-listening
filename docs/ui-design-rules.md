# UI デザインルール（拘束ルール）

制定: 2026-11-21（オーナー指示）。本書はミミトレの全 UI 作業に適用される拘束ルールである。
実装担当（DSH）と監督者（Muse）の双方が従う。違反のある UI 変更はマージしない。

背景資料: 競合5アプリの画面比較と共通原則の策定（2026-11-21）。原則の根拠はそちらを参照。

## 1. 原則とルール

### P1. 1画面1タスク
- R1.1 画面の目的は1文で言えること。言えない画面は分割する。
- R1.2 プライマリボタン（最も目立つ実行ボタン）は1画面に1つだけ。
- R1.3 ファーストビュー内の操作要素は、主要1 + 補助 最大4まで。

### P2. 段階開示
- R2.1 初期表示の情報ブロックは5つまで。6つ目以降はタップ・展開・ボトムシートの奥に置く。
- R2.2 設定系・補助操作（速度変更、区間リピート等）は常時表示せず、開示の奥に置く。
- R2.3 解説文・凡例は常設しない。対象要素のタップで開く。

### P3. 固定枠は最小
- R3.1 固定ヘッダーは「戻る + タイトル1行 + 進捗表示」まで。
- R3.2 常時表示の操作列は画面下部1段まで。再生系はこの1段に集約する。
- R3.3 コンテンツ領域が画面面積の主役であること（固定枠が半分を超える画面は作らない）。

### P4. 可視化 > 文章
- R4.1 状態とフィードバックは数値・色・ゲージ・波形などの可視化を第一選択とする。
- R4.2 説明文は1ブロック最大2行。仕様説明（内部の動作説明）は学習画面に出さない。
- R4.3 スコアや進捗は文章でなく指標として表示する（1カード=1指標）。

### P5. 内部情報は出さない
- R5.1 生成パイプライン名、モデル名、config ID、ハッシュ等の開発・運用情報をユーザー画面に表示しない。例外なし。
- R5.2 内部都合の件数・状態表示（生成完了、合計回数の内部カウンタ等）をユーザー向け文言に混ぜない。
- R5.3 違反を見つけた場合はバグとして扱い、機能追加より優先して除去する。

### P6. モードは混ぜない
- R6.1 異なる活動（聞く/読む/話す/確認する）は排他モードとして切り替える。縦積みしない。
- R6.2 1画面にセクション見出しを2つ以上並べない。
- R6.3 各モードはその活動に必要な UI だけを持つ。他モードの部品を残さない。

### P7. 部品と階層の統一
- R7.1 ボタンは3種のみ（プライマリ=青フィル / セカンダリ=枠線 / テキスト）。
- R7.2 文字階層は見出し・本文・補助の3段まで。余白は8ptグリッドに従う。
- R7.3 同じ意味の操作は全画面で同じ見た目にする。新しい見た目を作る前に既存部品で代替できないか検討し、代替不可なら本書に部品として追記してから使う。

## 2. 運用ルール（ワークフロー）

- W1. UI 変更を含む作業指示（DSH プロンプト等）には、本書への準拠を必須条件として明記する。
- W2. UI 変更を含む PR には、変更した全画面のスクリーンショット添付が必須。
- W3. UI 変更を含む PR には、第3節のチェックリストを PR 本文に含め、全項目パスがマージ条件。
- W4. 監督者はマージ前に、スクリーンショットとコードで数値基準（ブロック数、ボタン数、内部文字列の有無）を検証する。検証できない PR はマージしない。
- W5. 例外はオーナーの明示承認がある場合のみ認め、第4節の例外台帳に記録する。承認のない例外は差し戻す。
- W6. 既存違反は第5節の台帳で管理し、フェーズ計画に従って解消する。新規違反の追加は禁止（現状より悪化させない）。
- W7. リリース（審査提出・TestFlight 配信を含む）前には、全画面をライトモードとダークモードの両方で実画面撮影し、文字の視認性を検証する。片方のモードしか確認していない場合は提出しない。（2026-11-21 のダークモード障害を受けた追加）
- W8. 診断・クイズ等の設問は、正解そのものを設問文に含めない。また正解の選択肢の位置がデータ順に固定されないよう、設問ごとに表示順をシャッフルし、正解が全問で同じ位置（先頭など）にならないようにする。設問データは提出前に全問を通して目視確認する。（2026-11-21 の診断設問の不備を受けた追加）

## 3. マージ前チェックリスト（スクリーンショットで数える）

- [ ] P1: プライマリボタンが1つだけか。操作要素が主要1+補助4以内か
- [ ] P2: 初期表示の情報ブロックが5つ以下か
- [ ] P3: 固定枠が「上部（戻る+タイトル+進捗）」「下部1段」以内か
- [ ] P4: 2行を超える説明文ブロックがないか
- [ ] P5: 内部文字列（パイプライン名、モデル名、ID、内部カウンタ）が0か
- [ ] P6: セクション見出しが1画面に2つ以上ないか
- [ ] P7: 新しい見た目のボタン・ラベルを作っていないか
