# ミミトレ 計測設計

最終更新: 2026-11-22（v1.1 GA4 送信基盤を導入）

事業の最重要目的は「リリース」ではなく、インストールしたユーザーが使い続け、課金につながることです。その判断に使う指標と、アプリが記録するイベントを定義します。

## 1. 現状の制約（正直な現状）

- v1.0 の分析は **端末内イベントログのみ**（`src/features/analytics/analyticsStore.ts`）でした。v1.1 からは同じイベントを **GA4（Firebase Analytics）にも送信**します（2026-11-22 ユーザー指示「iOS/Android/Web のすべての分析に GA4 を活用」により、送信基盤の GM 判断は確定）。
- 送信先は Firebase プロジェクト「mimitore」（`mimitore-84015`）。GA4 プロパティは Web と共通の「33eigo」（プロパティ ID `565384874`、Web 測定 ID `G-ZFDHY4K5NS`）です。
- **保留事項（2026-11-22 時点）**: Firebase プロジェクトと GA4 プロパティのリンクには GA4 アカウントレベルの管理者権限の付与が必要で、リンクは未完了です。リンク完了後にアプリのイベントが GA4 プロパティ側に表示され、下記 KPI が算出可能になります。それまでは TestFlight 期の定性確認が前提です。
- 記録・送信するイベントには個人を特定する情報を含めません（端末内連番とローカル時刻、レッスン ID 等のみ。GA4 側の集計は Firebase の自動収集識別子によります）。

## 2. 記録イベント（実装済み）

| イベント | 意味 |
|---|---|
| `app_first_open` | 初回起動 |
| `onboarding_started` | 初回診断の開始 |
| `onboarding_completed` | 初回診断の完了（Aha 体験の到達） |
| `onboarding_skipped` | 初回診断のスキップ |
| `lesson_started` | レッスン再生開始 |
| `lesson_completed` | レッスン最後まで再生 |
| `shadowing_recorded` | シャドーイング録音の完了 |
| `paywall_viewed` | ペイウォール表示 |
| `purchase_completed` | 購入完了 |

## 3. KPI 定義（ローンチ期）

| 指標 | 定義 | 目標（仮説） |
|---|---|---|
| North Star | 週に3回以上レッスンを完了した学習者数（要: ユーザー識別と集計基盤。v1.0 の端末内ログでは算出不可。v1.1 の GA4 送信開始後、Firebase↔GA4 リンク完了を条件に算出可能） | 継続成長 |
| Aha 到達率 | `onboarding_completed` ÷ 初回起動 | 60%以上 |
| 継続率 D7 | 初回起動から7日後に再訪した割合（要: ユーザー識別と集計基盤。v1.0 の端末内イベントだけでは算出不可。v1.1 で GA4 が自動収集するセッション・再訪と組み合わせ、リンク完了後に算出可能） | 30%以上（クローズドテスト期の目安） |
| 利用頻度 | 1ユーザーあたり週のセッション数（同上、現状は算出不可） | 3回以上 |
| 課金ファネル | `paywall_viewed` → `purchase_completed` の転換率。ただし `purchase_completed` は復元時にも発火するため、集計では payload の `restored: true` を除外する。トライアル開始率は `trial_started` イベントが未実装のため現状は計測不可 | 初期は実測して基準を作る |

## 4. 判断の cadence

- ローンチ直後: TestFlight／初期ユーザーのイベントと定性フィードバックで、Aha 体験（60秒診断→聞き取れなかった理由の可視化）が刺さっているかを最優先で確認する。
- 送信基盤（GA4）は v1.1 で導入した。Firebase↔GA4 リンクの完了後、GA4 の自動収集（ユーザー識別・セッション）と本書のイベントを組み合わせて KPI をダッシュボード化する（D7・利用頻度・North Star はリンク完了後に算出可能になる）。イベント名と意味は本書を正とし、変更時は本書を先に更新する。
