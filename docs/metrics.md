# ミミトレ 計測設計

最終更新: 2026-11-21（v1.0.0）

事業の最重要目的は「リリース」ではなく、インストールしたユーザーが使い続け、課金につながることです。その判断に使う指標と、アプリが記録するイベントを定義します。

## 1. 現状の制約（正直な現状）

- v1.0 の分析は **端末内イベントログのみ**（`src/features/analytics/analyticsStore.ts`）。外部送信・集計基盤は未導入です。
- したがって現時点では、下記 KPI を全体集計で継続観測することはできません。TestFlight 期の定性確認と、v1.1 での送信基盤導入（要 GM 判断）が前提です。
- 記録するイベントには個人を特定する情報を含めません（端末内連番とローカル時刻、レッスン ID 等のみ）。

## 2. 記録イベント（実装済み）

| イベント | 意味 |
|---|---|
| `app_first_open` | 初回起動 |
| `onboarding_started` | 初回診断の開始 |
| `onboarding_completed` | 初回診断の完了（Aha 体験の到達） |
| `onboarding_skipped` | 初回診断のスキップ |
| `lesson_started` | レッスン再生開始 |
| `lesson_completed` | レッスン最後まで再生 |
| `shadowing_recorded` | シャドーイング録音の完了 |
| `paywall_viewed` | ペイウォール表示 |
| `purchase_completed` | 購入完了 |

## 3. KPI 定義（ローンチ期）

| 指標 | 定義 | 目標（仮説） |
|---|---|---|
| North Star | 週に3回以上レッスンを完了した学習者数 | 継続成長 |
| Aha 到達率 | `onboarding_completed` ÷ 初回起動 | 60%以上 |
| 継続率 D7 | 初回起動から7日後に再訪した割合 | 30%以上（クローズドテスト期の目安） |
| 利用頻度 | 1ユーザーあたり週のセッション数 | 3回以上 |
| 課金ファネル | `paywall_viewed` → `purchase_completed` の転換率、トライアル開始率 | 初期は実測して基準を作る |

## 4. 判断の cadence

- ローンチ直後: TestFlight／初期ユーザーのイベントと定性フィードバックで、Aha 体験（60秒診断→聞き取れなかった理由の可視化）が刺さっているかを最優先で確認する。
- 送信基盤を入れるタイミングで、本書の KPI をそのままダッシュボード化する。イベント名と意味は本書を正とし、変更時は本書を先に更新する。
